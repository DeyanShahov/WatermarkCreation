# Watermark Creation

**Приложение за добавяне на водни знакове на снимки с GPS, метео, QR код и стъпки**

Watermark Creation е уеб приложение (PWA), работещо напълно локално в браузъра, което позволява добавяне на водни знакове върху снимки. Изработено е за ползване на мобилни устройства и десктоп, без нужда от интернет връзка след първоначалното зареждане.

## ✨ Функционалности

### Работи веднага (v1.2.0)
- **🔢 Бърза маркировка с номер** — избор на снимки, позиция на номера (↖ ↗ ↙ ↘), еднокликовно прилагане
  - **Два начина на нумиране**: Последователно (1, 2, 3…) или Групово (едно число за всички избрани снимки)
- **🗺️ Пълен GPS воден знак** — класически панел с координати (десетични + DMS), точност, надморска височина, дата/час, **адрес (улица, град — автоматично от геокодиране)**, **температура и влажност (автоматично от метео API)**, QR код с навигация до координатите, бранд/текст
- **🔢🗺️ Воден знак + цифра** — комбинация от горните два: GPS панел + отделна цифра в ъгъл (само горе-ляво), с опционален текст след цифрата
- **🤖 AI валидация на адрес** — въведете адрес, натиснете „AI Валидация“ → поправен/пълен адрес с уточнени координати
- **🔍 Автоматично геокодиране** — въведете адрес → натиснете „Преглед на координати“ → автоматично извличане на координати (улично ниво), адрес и метео данни
- **🖼️ Бърз преглед на снимки** — двойно кликване върху тумбнейл отваря снимката в пълен размер; затваряне с клик, Escape, ✕ или клик извън снимката
- **📁 Категории и стъпки** — йерархична структура: Категория → Стъпки → Снимки
- **🖱️ Drag & Drop подреждане** — промяна на реда на категории, стъпки и снимки чрез дъргане
- **💾 Локално запазване** — всичко в IndexedDB, работи офлайн
- **📊 Статистики** — брой снимки, категории, стъпки, присвоени снимки
- **📱 PWA поддръжка** — инсталира се като приложение, работи офлайн, maskable икони

### В разработка (будущи версии)
- 🤖 **AI анализ на снимки** — автоматично разпознаване на обекти/ситуации, четене на съществуващи водни знаци, извличане на EXIF/GPS/дати, хронологично подреждане

## 📖 Как да работите

### 1. Заредете снимки
Натиснете **„Зареди снимки“** → изберете файлове → снимките се показват в **Галерията**

### 2. Създайте категория
**Категории** → **„Добави категория“** → име, описание, ред → **„Запази“**

### 3. Добавете стъпки
Кликнете на категория → **„Добави стъпка“** → име, описание, необходим брой снимки, ред → **„Запази“**

### 4. Присвоете снимки
В категорията → **„Присвои снимки“** до стъпката → отметнете снимки → **„Потвърди избор“**  
Редът се променя с **drag & drop** (⋮⋮ иконата)

### 5. Бърз преглед на снимки (нова функция)
В **Галерията** или в **Стъпките** — **двойно кликнете** върху снимка → отваря се в пълен размер за детален преглед  
За затваряне: **кликнете върху снимката**, натиснете **Escape**, кликнете **хоризонтално извън снимката** или бутона **„✕“**

### 6. Бърза маркировка с номер
В **Галерията** отметнете снимки → **„Обработи избраните“** → изберете позиция (↖ ↗ ↙ ↘)
- **Начин на нумиране** (ново):
  - **Последователно** (по подразбиране) — снимките получават номера 1, 2, 3… според реда на избор
  - **Групово** — всички избрани снимки получават **едно и също число** (въвежда се в полето „Стойност за бадж/воден знак“)
→ **„Приложи“**

### 7. Изтеглете резултати
След обработка → **„Изтегли всички“** → файлове като `IMG_20241116_143022_#1.jpg`

## 🔧 Конфигурация

### Environment променливи (`.env`)
```env
# Опционално - за weather API (ако се използва външен provider)
VITE_WEATHER_API_KEY=your_key_here

# AI ключ за Netlify функцията (netlify/functions/ai-process.js).
# ВАЖНО: БЕЗ VITE_ префикс — така ключа НЕ се вплевва в бъръндъра,
# а се ползва само на сървъра като резервен (proxy) път.
GROQ_API_KEY=your_groq_key_here

# Опционално:
AI_ENDPOINT=https://api.groq.com/openai/v1/chat/completions
AI_MODEL=qwen/qwen3.8-27b
```
`.env` е в `.gitignore`. За локален тест: `netlify dev` (чете `.env`). Онлайн стойностите се задават в Netlify → Site settings → Environment variables.

### Приоритет на AI ключа
1. **Браузърен ключ** — запазен за категория в IndexedDB (`category-prompts`) → директно към Groq.
2. **Сървърен ключ** — `GROQ_API_KEY` от Netlify environment variables → резервен път чрез `/.netlify/functions/ai-process`.
3. И двете липсват → видимо съобщение за грешка.

Ключът на потребителя никога не напуска браузъра и **не** се включва в JSON архива (`categories-archive.json`) — импорт/експорт работи само с категории и стъпки.

### Геокодиране (Nominatim proxy + fallback)

В модала „Конфигурация на воден знак за категория" панелът показва две неща:

- **Пълен адрес** — цялата улица с номер, пощенски код и град (напр. `Bäckenäckerstraße 5, 91077 Neunkirchen am Brand`).
- **Име на мястото** — само градът (напр. `Neunkirchen am Brand`).

Данните идват от две стъпки:

1. **Nominatim proxy** (`netlify/functions/geocode`) — улично ниво, „Увереност 100%". Изисква хостване на функцията: Netlify/Vercel, или локално с `netlify dev`.
2. **Fallback Open-Meteo** — само ниво град, „Увереност 80%", отнема няколко секунди (множество търсения с лимит 1 заявка/сек). Това са координати на центъра на населеното място, не на улицата.

Ако proxy-то не е наличен (напр. статичен хостинг на `dist/` като GitHub Pages), приложението:
- **запазва пълния адрес** от въведените/AI-валидирани данни (не го замества само с града);
- показва в статуса предупреждение: „⚠️ Геокодирането е на ниво град (Nominatim proxy не е наличен)".

Env променлива за User-Agent на Nominatim: `NOMINATIM_USER_AGENT` (без `VITE_` префикс).
```bash
# Локално тестване на функциите (чете .env)
npx netlify dev
```

## 📦 Deployment

### GitHub Pages
```bash
npm run build
# Качете съдържанието на dist/ в gh-pages branch
```

### Netlify / Vercel / Firebase Hosting
```bash
# Build command: npm run build
# Output directory: dist
# Install command: npm install
```

> **Serverless функциите** (`netlify/functions/`) се качват само на Netlify/Vercel. За улично-ниво геокодиране и AI proxy задай environment променливите (`GROQ_API_KEY`, `NOMINATIM_USER_AGENT`) в панела на хоста.
>
> При статично хостване на само `dist/` (GitHub Pages, Firebase Hosting, nginx) функциите не съществуват: геокодирането е на ниво град (fallback Open-Meteo), а AI изисква браузърен ключ на потребителя.

### Docker (опционално)
```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
